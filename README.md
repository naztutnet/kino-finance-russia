# Финансирование кино в России

Интерактивный справочник для продюсеров и авторов кинопроектов: подбор источников финансирования, каталог фондов и региональных программ, календарь дедлайнов, требования к подаче и личный список заявок.

**Опубликованный сайт:** https://naztutnet.github.io/kino-finance-russia/

## Возможности MVP

- подбор источников по типу проекта, стадии, региону, категории и признаку дебюта;
- отдельный каталог всех источников;
- быстрый фильтр «Приём открыт сейчас»;
- календарь подачи заявок, защит и публикации результатов;
- подписка на общий календарь в формате `.ICS`;
- прямые официальные ссылки на результаты — только после проверки конкретной страницы итогов;
- блок «Требования к подаче» в карточках:
  - перечень документов;
  - способ подачи;
  - сроки и ограничения;
  - официальные формы, положения и регламенты;
  - явная пометка «Нет данных», когда официальный комплект не найден;
- избранное и раздел «Мои подачи»;
- статусы пользователя: «Планирую подаваться», «Заявка подана», «Жду результаты», «Не подходит»;
- сравнение до четырёх источников;
- персональные напоминания `.ICS`;
- экспорт результатов подбора в CSV и PDF через печать браузера;
- копирование ссылки с параметрами подбора.

## Хранение пользовательских данных

Избранное, статусы заявок и список сравнения хранятся локально в браузере через `localStorage`.

Это означает:

- регистрация не требуется;
- данные не отправляются на сервер;
- данные не синхронизируются между Safari, Chrome, Яндекс Браузером и другими устройствами;
- очистка данных сайта в браузере удалит избранное и статусы.

Ключ хранилища: `kino-finance-mvp-v1`.

## Данные карточки

Основные поля источника находятся в файлах `data-*.json`:

- `id` — стабильный идентификатор;
- `org` и `program` — организатор и программа;
- `category` — государственный, частный, региональный, питчинг, грант или международный;
- `types` — поддерживаемые типы проектов;
- `stage` — стадия проекта;
- `region` — региональное ограничение;
- `max_amount_text`, `coverage_pct`, `returnable` — условия финансирования;
- `deadline_text`, `defense_date`, `results_date` — сроки;
- `status` и `results_summary` — текущий статус;
- `link`, `apply_link`, `results_link` — официальные страницы;
- `verification_status`, `verified_at` — статус и дата проверки.

## Требования к подаче

`requirements.js` добавляет раскрывающийся блок к каждой карточке.

Для источников, по которым требования подтверждены официальными страницами, показываются конкретные документы и способ подачи. Сейчас отдельные проверенные правила подготовлены для:

- Фонда кино;
- Минкультуры России;
- Института развития интернета;
- Президентского фонда культурных инициатив;
- Фонда поддержки регионального кинематографа;
- Кинопрайма.

Для остальных карточек выводится честная заглушка с указанием, где искать сведения: в положении, регламенте, постановлении региона, форме конкурса или FAQ. Типовые предположения не выдаются за официальные требования.

## Правила работы с результатами

Кнопка «Результаты» должна вести только на страницу или документ с итогами конкретного отбора.

Не допускается использовать в качестве ссылки на результаты:

- главную страницу организации;
- общую страницу программы без списка победителей;
- форму подачи заявки;
- неподтверждённую публикацию стороннего сайта.

Проверенные ссылки хранятся в `result-links.json` и/или в поле `results_link` карточки.

## Календарь

Календарь строится из всей базы источников.

Создаются отдельные события для:

- окончания приёма заявок;
- защиты или питчинга;
- публикации результатов.

Если организатор не указал точный день, сайт показывает «Дата ожидается». Такие записи не должны получать выдуманную дату и не включаются в `.ICS` как точные события.

## Локальный запуск

Из-за загрузки JSON через `fetch()` сайт нужно открывать через локальный HTTP-сервер, а не двойным кликом по `index.html`.

```bash
python3 -m http.server 8000
```

После запуска открыть:

```text
http://localhost:8000/
```

## Публикация

Сайт публикуется через GitHub Pages из ветки `main` с помощью workflow `.github/workflows/deploy-pages.yml`.

После изменения файлов:

```bash
git add .
git commit -m "описание изменения"
git push origin main
```

GitHub Actions соберёт и опубликует новую версию автоматически.

## Обновление данных

При изменении источника нужно:

1. проверить официальную страницу и действующий регламент;
2. обновить соответствующую запись в `data-*.json`;
3. указать дату проверки в `verified_at`;
4. добавить прямую ссылку на результаты, если они опубликованы;
5. обновить требования к подаче, если изменился комплект документов;
6. пересобрать календарь:

```bash
python3 scripts/rebuild_deadlines.py
python3 scripts/update_calendar.py
```

## Ограничения текущей версии

- нет серверной базы и авторизации;
- избранное не синхронизируется между браузерами;
- email-уведомления пока не реализованы;
- часть программ не публикует полный комплект документов в HTML — требуется проверка PDF-приложений и приказов;
- некоторые региональные программы объявляются нерегулярно;
- сайт не заменяет официальное положение конкурса и юридическую проверку заявки.

## Принцип достоверности

Если факт не удалось подтвердить официальным источником, он должен быть помечен как требующий уточнения. Отсутствующие сведения не заполняются предположениями.
